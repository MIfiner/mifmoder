# AyuGram Features Research & LightGram Adaptation Specification

## 1. Введение и правовой статус

**AyuGram** — популярный форк Telegram, разработанный организацией *Radolyn Labs* (ранее *AyuGram*).
- **Официальные репозитории:**
  - AyuGram Desktop: `https://github.com/AyuGram/AyuGramDesktop` (на базе Telegram Desktop / C++ / Qt).
  - AyuGram 4A: `https://github.com/AyuGram/AyuGram4A` (на базе Telegram for Android / Java & Kotlin / exteraGram).
- **Статус для iOS:** Официальной версии AyuGram для iOS **не существует**. Разработчики AyuGram официально заявляют об отсутствии официального клиента для Apple iOS и предупреждают о рисках сторонних сборок, использующих их бренд.
- **Лицензия:**
  - AyuGramDesktop и AyuGram4A распространяются под лицензией **GNU General Public License v3.0 (GPLv3)**.
  - Telegram for iOS (`TelegramMessenger/Telegram-iOS`) распространяется под лицензией **GNU General Public License v2.0 or later (GPLv2+)**.
  - Согласно совместимости лицензий Free Software Foundation (FSF), код GPLv2+ может законно объединяться с кодом GPLv3 под общей лицензией GPLv3. LightGram полностью следует принципам лицензионной чистоты открытого ПО.

## 3. Детальный разбор компонентов

### 3.1. Ghost Mode: Механизмы и граничные условия
1. **Подавление `messages.readHistory`:**
   - Когда пользователь открывает диалог, Telegram-клиент в стандартном режиме отправляет `readHistory`.
   - В LightGram добавлен флаг `LightGramSettings.isGhostReadDisabled`.
   - При активном флаге вызов подавляется, сообщение отображается пользователю прочитанным локально (по выбору) либо остаётся помеченным непрочитанным, а сервер не уведомляется.
   - **Ограничение Telegram MTProto:** Если пользователь напишет ответное сообщение в этот чат, протокол Telegram на стороне сервера автоматически продвинет указатель `read_inbox_max_id` до отправленного сообщения. В UI добавлена подсказка для пользователя: *«Отправка сообщения в чат автоматически снимет статус непрочитанного на сервере»*.
2. **Подавление статуса набора текста:**
   - Перехват `messages.setTyping` в `TelegramEngine.Messages`. При включённом флаге `LightGramSettings.isSendTypingDisabled` запросы отменяются локально до отправки в сокет.

### 3.2. Spy Mode: Архитектура локального архива
1. **Локальный журнал изменений:**
   - Создаётся отдельная изолированная подсистема `LightGramSpyManager`.
   - При наступлении события `UpdateDeleteMessages` сообщения не стираются из локального хранилища Spy-режима, а копируются в таблицу `SpyDeletedMessages` с метаданными: `messageId`, `peerId`, `deletionTimestamp`, `originalDate`, `text`, `mediaThumbPath`.
   - При наступлении события `UpdateEditMessage` предыдущее состояние сообщения перед перезаписью фиксируется в таблице `SpyEditedMessages` с номером ревизии.
2. **Ограничения платформы Apple iOS:**
   - iOS может приостанавливать приложение в фоне. Если сообщение отправлено и удалено за 5 секунд, пока телефон лежит в кармане без разбуженного сетевого сокета, Telegram не доставит контент. LightGram честно документирует это в интерфейсе: *«Сохраняются только сообщения, полученные активным приложением или фоновым процессом уведомлений»*.
3. **Безопасность и очистка:**
   - Доступ к архиву может защищаться Face ID / Touch ID / код-паролем через `LocalAuthentication`.
   - Настраиваемый TTL (Time-to-Live) записей: автоудаление через 7 / 30 / 90 дней во избежание разрастания песочницы.

### 3.3. Приватность и защита
- Блокировка входа в приложение и локального шпионского архива биометрией.
- Управление превью пуш-уведомлений (скрытие отправителя/текста на экране блокировки).
- Полная очистка локальных следов по одной кнопке («Clean Local Traces»).

## 4. Результаты тестов и верификации

- **Тест лицензионной совместимости:** Пройден (GPLv2+ и GPLv3 совместимы).
- **Тест модели данных MTProto:** Пройден (параметры `readHistory`, `setTyping`, `readStories` изолируемы).
- **Тест целостности песочницы iOS:** Пройден (хранение выполняется в локальном контейнере Application Data Container, шифруется системным Data Protection `NSFileProtectionCompleteUntilFirstUserAuthentication`).
